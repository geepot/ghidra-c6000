C6000 Processor Tools

The C6000 extension installs native processor languages, analyzers and a decompiler injection library. Those work without enabling the optional user-interface plugin. Enable C6000Plugin under File > Configure > Configure All Plugins to add the processor panel and actions.

Open Analysis > C6000 > Processor Tools. The dockable panel follows the current program and cursor, shows the selected timing and floating-point models, and reports whether the current function has an exact-schedule review. The same entry and schedule actions are available from the Listing and Decompiler context menus. Immutable program views allow preview and validation; entry setup, activation and disable require an editable program.

Choose the processor language

default and analysis use C64x/C64x+/C674x cross-path timing. c67x and c67x-analysis omit that stall on C67x/C67x+. Select the matching byte order on import. ELF auto-selection uses default. Analysis variants simplify floating-point flags and special rounding. All variants share a superset decoder; C67x ISA filtering and C66x-specific instructions are known gaps.

Start a raw image

Import with the correct language and base address. Place the cursor at an entry instruction and choose Set Entry Point Here. The native background command primes compact context, disassembles code, creates an entry function and marks the entry point. Ghidra's analyzers handle subsequent analysis. Cancellation or refusal rolls back the command; Undo restores the prior program.

Review exact packet schedules

Ordinary instruction lifting does not model all parallel reads and delayed writes. Exact scheduling is explicit and per function. It requires evidence that there are no pending instruction effects or transfers at entry. A function boundary or calling convention is not that evidence.

  1. Select a defined function and choose Review Exact Schedule.
  2. Describe the entry evidence and any registers written during the preceding E1 cycle. Empty means none. Valid register names are A0–A31 and B0–B31.
  3. Choose the source-byte range supporting the evidence. Addresses are hexadecimal and the end is inclusive. The range must cover whole initialized 32-byte fetch packets, up to 64 KiB. The default is the entry's fetch packet; change it when the evidence comes from setup or caller code.
  4. Choose Preview schedule. Preview is read-only. Unsupported phases, incomplete function ownership or other contract failures are displayed without enabling a schedule. Functional-unit and memory-transfer-path conflicts are refused even when the instructions use complementary predicates.
  5. Review the result, then choose Enable reviewed schedule. Activation rechecks bytes, language, context, ownership and references while analysis is suspended. The activation and review are one undoable transaction.

Editing inputs invalidates the preview. Cancel leaves the program unchanged. Reopening a review restores its previous inputs and requires a fresh preview. Reviews pinning multiple source ranges must be renewed through their API/batch workflow.

Validate Exact Schedule checks a recorded review after edits. A stale review is refused by the decompiler as well; it never silently becomes an ordinary sequential representation. Re-preview and explicitly enable a fresh review if the source or assumptions changed. Operation messages clear when you navigate to another function or edit the program.

Disable Exact Schedule explicitly restores ordinary instruction lifting, removes the function’s review and observation contracts, and preserves ownership, comments and references. It is undoable. A stale schedule is never automatically disabled.

Internal context and scheduler registers are hidden from normal Listing assumptions through the processor specification. Enable Ghidra’s Display Hidden Registers option to inspect them.

Native actions do not invoke scripts or require JSON manifests. Scripts remain available for headless/batch use, trace experiments and fixture verification. Closed-call and post-return observation contracts remain advanced APIs; the GUI does not infer them.
