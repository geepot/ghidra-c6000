# Provenance, sources and licensing

This directory is an independent Ghidra processor extension for the Texas
Instruments TMS320C6000 DSP family (C64x, C64x+, C67x, C67x+ and C674x). It is
licensed under the Apache License, Version 2.0, the same licence Ghidra itself
uses, which is only possible because the implementation was written from
public documentation rather than derived from any existing disassembler.

## Primary authority

Every encoding and every semantic rule in `data/languages/` is traceable to a
numbered figure, table or section of:

* **SPRUFE8B** - *TMS320C674x CPU and Instruction Set Reference Guide*,
  Texas Instruments, literature number SPRUFE8B, July 2010.
  The authoritative source for the instruction encoding maps (appendices C-H),
  the instruction descriptions (section 3.12), the compact fetch-packet header
  (section 3.10), the condition encoding (Table 3-9), the .D addressing modes
  (Table C-3), the control-register addresses (Table 3-27) and the branch
  semantics (the per-instruction Execution blocks).
  <https://www.ti.com/lit/ug/sprufe8b/sprufe8b.pdf>
* **SPRU732J** - *TMS320C64x/C64x+ DSP CPU and Instruction Set Reference Guide*,
  Texas Instruments, July 2010. Figure C-4 and the LL, SL, and CMTL instruction
  descriptions supply the C64x+ linked-word encodings and CPU-visible behavior.
  <https://www.ti.com/lit/ug/spru732j/spru732j.pdf>
* **SPRUH91D** - *TMS320C6745/6747 Fixed/Floating-Point DSP Technical Reference
  Manual* and **SPRS590** - *TMS320C6747 data sheet*, for the C6745/C6747
  control-register and memory-map details.
* **SPRU187 / the C6000 Optimizing Compiler User's Guide**, for the C6000
  calling convention recorded in `data/languages/c6000.cspec`.

No TI PDF, and no text extracted from one, is redistributed in this
repository. `tools/build_encodings.py` reads a locally extracted text dump of
SPRUFE8B and regenerates the encoding table; the dump itself is not committed.

## Other implementations consulted

These were used only as **test oracles or for cross-checking**, never as a
source of code:

* **GNU binutils** (`objdump -m tic6x`, `as -march=c674x`) - GPLv3+. Used to
  produce independent disassembly for the corpus comparison. Built locally at
  test time; nothing from binutils is vendored here.
* **Capstone** (`CS_ARCH_TMS320C64X`) - BSD-3-Clause. Used as a weak
  cross-check only. It is known to decode compact fetch packets incorrectly,
  to apply the *s* bit where the *y* bit selects the .D-unit base register, and
  to render opfield `111011` as `SUBAB` instead of `SUBAW`; the corpus test's
  `.D`-unit cases exist specifically to pin those three behaviours down.
* **cdj2000-emulator** - a GPL-2.0-or-later QEMU C674x core. Consulted as an
  independent behavioural oracle during development only; no code was copied
  and it is not a build dependency of this extension.

## Generated files

`data/languages/c6000_decode.sinc` and `data/languages/c6000_placeholders.sinc`
are generated by `tools/gen_decode.py` from the SPRUFE8B-derived encoding table.
They are committed so that the extension can be built without the manual, but
they are build products of the transcription and are marked as generated at the
top of each file.
